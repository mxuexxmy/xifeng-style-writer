# Writing SOP

这份 SOP 用来指导起稿、改稿和风格诊断。

## 1. 起稿前

先填这张四格表：

- 题目：这篇文章表面上在讲什么？
- 命题：这篇文章真正想说什么？
- 误读：大多数人会怎么看错？
- 结论：读者最后应该带走什么判断？

如果这四格填不出来，不要急着写正文。

## 2. 选题归类

先判断文章属于哪一种：

- 思想/认知类
- 资产配置类
- 交易/量化类
- 宏观分析类
- 人生建议类
- 综合杂谈类

不同题型，例子来源不同：

- 思想/认知：人物、冲突、误判
- 资产配置：房产、黄金、美元、仓位、现金流
- 交易/量化：策略、时间、赔率、纪律、风险控制
- 宏观分析：国家、产业、汇率、制度、就业
- 人生建议：读书、择业、婚恋、孩子、家庭
- 综合杂谈：热点事件、影视文本、公共人物

## 3. 结构模版

默认用五段式：

1. 钩子
2. 表层解释
3. 转角
4. 机制展开
5. 冷结论

### 1. 钩子

入口通常从这几类里选：

- 读者留言
- 最近一个事件
- 一个公众人物
- 一个广泛误解
- 作者前文留下的问题

目标不是交代背景，而是让读者迅速进入问题。

### 2. 表层解释

先把多数人的直觉讲出来。

例如：

- 很多人觉得这是道德问题
- 很多人觉得这只是市场问题
- 很多人觉得这无非是一个个人选择

### 3. 转角

这一步最关键。

常见句式：

- 这么理解不能说全错，但只说到了皮毛
- 问题不在这里
- 如果你只看到这一层，就会误判
- 说白了，这件事根本不是在讲 X

### 4. 机制展开

这是正文主体，至少拆三层：

1. 谁在得利
2. 谁在承担成本
3. 结构为什么会持续复制这件事

必要时补第四层：

4. 普通人该如何理解自己的位置

### 5. 冷结论

结尾不要总结情绪，要总结规则。

结尾应该像：

- 一句更冷的判断
- 一条更硬的建议
- 一个更本质的翻译

## 4. 例子怎么选

好例子要满足三件事：

- 具体
- 可替代抽象概念
- 能把论点往下推一层

优先级：

1. 真实人物或读者情境
2. 职场或交易场景
3. 历史类比
4. 影视或公众事件

不要为了热闹堆太多例子。

通常一个主例子，外加一到两个辅助例子，就够了。

## 5. 改稿 SOP

改稿时按下面顺序删改：

1. 删掉背景复述过长的段落
2. 删掉只有态度没有推进的段落
3. 删掉空泛抒情
4. 给抽象判断补一个具体例子
5. 把长段拆短
6. 检查每一段是否都在推动论证
7. 把结尾压得更冷、更短、更像结论

## 6. 文件输出 SOP

如果最终产物是一篇文章或改写稿，默认执行下面动作：

1. 把最终稿整理成 Markdown
2. 一级标题使用文章标题
3. 正文后附上 `备用标题`
4. 文件名默认使用文章标题
5. 保存到：
   `/Users/linzhenyuan/Desktop/obsidian/03-内容素材/草稿`
6. 默认不要在其他目录保留副本

只有在下面情况才偏离这个默认流程：

- 用户明确要求只在对话里展示
- 用户明确要求另存到别的路径
- 用户明确要求同时保留多个副本

## 7. 风格诊断 SOP

如果要判断一篇文章像不像“西风”，按这五项打分：

1. 标题是否有转角
2. 开头是否快速入题
3. 中段是否有机制拆解
4. 是否始终在对读者说话
5. 结尾是否落成规则

## 8. 最低合格标准

一篇合格的稿子，至少要满足：

- 不是新闻复述
- 不是鸡汤议论文
- 不是纯情绪宣泄
- 至少有一个结构转角
- 至少有一个具体例子
- 结尾能压成一句判断
